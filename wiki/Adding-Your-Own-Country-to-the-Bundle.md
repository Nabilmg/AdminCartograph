# Adding a Country to the Bundle

The recommended way to add a country is via the [Custom Geometry
Upload](Custom-Geometry-Upload.md) flow at runtime — no rebuild
needed. The bundle exists for users who want a self-contained
`.pbiviz` to share without any setup. This page covers the bundle
path.

## Three steps

```bash
# 1. Drop a fieldmaps.io <ISO3>.geojson.zip into country-geojson/
cp ~/Downloads/KEN.geojson.zip country-geojson/

# 2. Rebuild
npm run release

# 3. Import the new releases/AdminCartograph.pbiviz
```

The whole pipeline runs:

1. **`scripts/sync-countries-from-geojson.js`** unzips every
   `country-geojson/<ISO3>.geojson.zip` into
   `scripts/data/raw/<ISO3>/`, detects the deepest available admN
   file, and rewrites `scripts/data/countries.json`.
2. **`scripts/build-topojson.js`** reads each country's adm1 +
   (optional) adm2 GeoJSON, normalises the property names, builds
   one combined TopoJSON at `assets/geometry/world.topojson.json`,
   and writes the country dropdown options to
   `src/generated/countries.ts`.
3. **`pbiviz package`** bundles the visual's TypeScript / CSS / SVG
   icon together with the new TopoJSON into a fresh `.pbiviz`.

## File naming

The script expects each zip to be named **`<ISO3>.geojson.zip`** —
uppercase ISO-3 letters only. If you drop in a lowercase or
mis-named file, normalise first:

```bash
git mv country-geojson/ken.geojson.zip country-geojson/KEN.geojson.zip
# or just
mv country-geojson/ken.geojson.zip country-geojson/KEN.geojson.zip
```

## What's inside a fieldmaps.io zip

Each zip from <https://fieldmaps.io/data/cod/originals/> contains
multiple admin levels in GeoJSON form. After extraction:

```
scripts/data/raw/KEN/
  ken_adm0.geojson    Country outline (not used)
  ken_adm1.geojson    Counties (used for Admin1 layer)
  ken_adm2.geojson    Sub-counties (used for Admin2 layer, if present)
  ken_adm3.geojson    Locations (not used — visual is two-level)
```

The build picks the highest available level ≤ 2 per country (so a
country shipping ADM0/1/2/3 contributes ADM1 + ADM2; one shipping
only ADM0/1 contributes ADM1 only and the visual auto-detects no
Admin2 layer for that country).

## Property names accepted

The pipeline reads from these fields, in order, and writes the first
non-empty one as the canonical property:

| Canonical | Reads from |
|---|---|
| `ADM1_PCODE` | `ADM1_PCODE`, `ADM1PCODE`, `adm1_pcode`, `PCODE_1` |
| `ADM1_EN` | `ADM1_EN`, `ADM1_NAME`, `ADM1EN`, `name_1`, `NAME_1` |
| `ADM2_PCODE` | `ADM2_PCODE`, `ADM2PCODE`, `adm2_pcode`, `PCODE_2` |
| `ADM2_EN` | `ADM2_EN`, `ADM2_NAME`, `ADM2EN`, `name_2`, `NAME_2` |

If your source uses a different convention (`STATE_ID`, `REGION`, …),
either:

- Pre-rename the properties in your GeoJSON before zipping, or
- Edit `scripts/build-topojson.js`'s `pickProp` candidate list to
  recognise your names.

## Bundle size budgets

Every country added grows the `.pbiviz`. Power BI's hard limit is
~50 MB per visual; practical loading time gets noticeable past 5 MB.

| Countries | Approx `.pbiviz` size at default simplify |
|---|---|
| 1 | ~150 KB |
| 8 (current bundle) | ~630 KB |
| 25 | ~2-3 MB |
| 50 | ~5-6 MB |
| 100+ | ~12-15 MB |

For very large bundles, increase the simplification weight:

```bash
node scripts/build-topojson.js --simplify 0.001 --quantize 5000
```

(See [Build Pipeline](Build-Pipeline.md) for a full description of
the flags.)

## Auto-generated dropdown

After every successful build, the country dropdown in the format
pane is regenerated from the bundle. The build writes
`src/generated/countries.ts`:

```ts
// AUTO-GENERATED by scripts/build-topojson.js. Do not edit.
export interface BundledCountry { iso: string; name: string; }
export const BUNDLED_COUNTRIES: BundledCountry[] = [
  { "iso": "AFG", "name": "Afghanistan" },
  { "iso": "COD", "name": "DR Congo" },
  ...
];
```

`src/settings.ts` imports `BUNDLED_COUNTRIES` and uses it to populate
the dropdown items at compile time. So the dropdown always matches
the bundle without any manual sync.

## Removing a country

```bash
rm country-geojson/HTI.geojson.zip
npm run release
```

The next build excludes Haiti and the dropdown drops the Haiti row.

## Per-country builds (advanced)

If you want a separate `.pbiviz` per country (each with its own GUID,
display name, and trimmed bundle), use the optional secondary
pipeline:

```bash
node scripts/release-all.js
```

This iterates every zip in `country-geojson/` and produces
`releases/admChoroplethBubbleMap-<ISO>.pbiviz`. Each release has a
distinct GUID derived from the ISO code so Power BI treats them as
sibling visuals — you can drop AdminCartograph-Sudan and
AdminCartograph-Yemen onto the same report canvas without conflict.

The default `npm run release` produces only the unified bundle; this
is the recommended distribution.
